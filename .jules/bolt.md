## 2024-05-17 - [Infinite render loops caused by useCallback and useEffect dependencies]
**Learning:** In React, if a `useCallback` modifies a piece of state that it also depends on (directly or indirectly via a variable tracking it), and that `useCallback` is then used as a dependency in a `useEffect` which auto-triggers it, it will result in an infinite render loop. This specific bug manifested because `isLoading` state was inside the dependency array of `handleProcess`, and `handleProcess` was inside the dependency array of an auto-triggering `useEffect`. When `handleProcess` updated `isLoading`, it caused a re-creation of `handleProcess`, which triggered the `useEffect`, which called `handleProcess`, creating a cycle.
**Action:** When tracking asynchronous state (like `isLoading`) to prevent simultaneous identical requests within a `useCallback`, it's safer to use a `useRef` (e.g., `isLoadingRef.current`) or omit it from the dependency array if you're certain it won't cause staleness. In this case, `useRef` provides functional mutability without triggering re-evaluations of the callback memoization. Additionally, when a `useEffect` auto-triggers an expensive operation on changes to input (like keystrokes), a debounce is essential to prevent hammering the API.
